# Wavelet / BCH Research UI

Локальная веб-оболочка для настройки, запуска и анализа исследований из пакета `research`.

## Архитектура

- FastAPI + SQLite хранят конфигурации и статусы экспериментов.
- Каждый запуск выполняется отдельным `python -m research.run_from_json` subprocess.
- stdout дочернего процесса содержит обычный лог и строки `PROGRESS {...}`.
- React/Vite отображает список запусков, прогресс, лог, таблицу `summary.csv` и Plotly-график.

## Docker

Из корня репозитория:

```bash
docker compose up --build
```

Интерфейс: http://localhost:3001

API: http://localhost:8001

(Порты `8001`/`3001` установлены по умолчанию, чтобы избежать конфликтов с другими проектами. Если нужны другие значения, их можно переопределить через переменные окружения:)

```bash
BACKEND_PORT=8000 FRONTEND_PORT=3000 docker compose up --build
```

Проверка: `GET http://localhost:8001/api/health`

Результаты сохраняются в `research_results/`, SQLite и пользовательские данные в `webapp_data/`.

## Локальный запуск

Backend:

```bash
pip install -r webapp/backend/requirements.txt
uvicorn app.main:app --app-dir webapp/backend --reload --port 8000
```

Frontend в отдельном терминале:

```bash
cd webapp/frontend
npm install
npm run dev
```

## Рабочий процесс

1. Выберите встроенный пресет в форме нового эксперимента.
2. Настройте число сообщений, seed, Eb/N0 и декодеры.
3. Проверьте конфигурацию. Backend построит реальные `G` и `H`, проверит размеры, ранг и ортогональность.
4. Запустите эксперимент и наблюдайте SSE-статус и live-log.
5. После завершения откройте график, выберите метрику и шкалу Y или перейдите к данным.

## Создание custom presets

В форме **Новый эксперимент** встроенные и пользовательские presets показаны
отдельными группами. Текущую конфигурацию можно сохранить через **Save preset**.
Пользовательский preset можно открыть, изменить, дублировать или удалить;
удаление не затрагивает уже созданные эксперименты, поскольку запуск хранит
собственный snapshot runtime configuration.

Custom presets сохраняются в SQLite (`webapp_data/experiments.db`) и переживают
перезапуск Docker. Старые JSON-файлы из `webapp_data/presets/` автоматически и
идемпотентно импортируются в SQLite при старте backend. Сохранение, импорт и
дублирование preset не запускают эксперимент: запуск остаётся отдельным действием.

### Перенос custom preset

Выбранный custom preset можно экспортировать кнопкой **Export JSON**. Формат
`*.preset.json` содержит только безопасные данные настройки:

```text
schema_version = 1
format = wavelet-code-preset
name
description
config
```

Результаты эксперимента в preset JSON не входят. **Import JSON** валидирует
версию, формат и полную `ResearchConfigSchema`, создаёт новый preset с новым
локальным UUID и ничего не запускает автоматически.

### Clone experiment as preset

На странице эксперимента кнопка **Clone as preset** создаёт custom preset из
фактического `runtime_config.json`. Для CSV-only import кнопка отключена, потому
что `summary.csv` не содержит полной воспроизводимой конфигурации. Для локального
запуска и imported package с runtime config клонирование доступно и не запускает
новый эксперимент.

## Experiment Preview

Перед запуском конфигурация должна пройти backend Preview. Он строит фактическую
runtime configuration тем же adapter'ом, который используется runner, проверяет
кодовые матрицы и показывает группы сравнения по длине и `(n,k)`.

Preview выводит эффективные `syndrome_t`, `chase_inner_t`, `chase_p`, rate,
статус Hard/Soft MLD и причину пропуска при `k > max_k_for_mld`. Несовпадение
rate или decoder budget является предупреждением, а не запретом запуска.
Технически невозможная конфигурация остаётся ошибкой.

Текущий runner всегда использует common random numbers внутри каждой одинаковой
`(n,k)`-группы: seed зависит от базового seed, `n` и `k`, но не от семейства или
имени кода. Preview явно показывает этот режим и рассчитанный workload без
выдуманной оценки времени выполнения.

## Импорт готового `summary.csv`

Команда «Импорт эксперимента» в навигации позволяет загрузить уже
рассчитанный `summary.csv` (например, полученный от коллеги) и сразу
посмотреть графики/таблицы — **без повторного Monte-Carlo запуска**.

- Backend валидирует обязательные колонки (`code_name`, `code_family`, `n`, `k`,
  `decoder`, `ebn0_db`, `message_count`, `ber`, `frame_error_rate`) и семантику
  (диапазоны BER/FER, `success_count + failure_count == message_count`,
  согласованность `frame_error_rate`/`ber` с `frame_errors`/`bit_errors` и т.п.).
- Невалидный CSV отклоняется с конкретным списком причин, без создания эксперимента.
- Успешный импорт создаёт Imported Experiment с `source = "imported_csv"`,
  видимый в UI отдельным бейджиком, и открывается в той же странице
  результата, что и локально рассчитанные эксперименты (графики, таблица, фильтры).
- Импортированный из CSV эксперимент не имеет полного runtime config/лога:
  эти данные появляются только при импорте полного experiment package.

## Обмен результатами (experiment package)

Завершённый эксперимент можно экспортировать как один `.zip`-файл и передать
другому человеку:

1. Открыть завершённый эксперимент и нажать **Export**.
2. Отправить получившийся `.zip` другому человеку.
3. На другой установке: **Experiments → Import experiment → Experiment package**.
4. Графики, таблицы, runtime configuration и metadata становятся доступны без повторного запуска.

Формат пакета: `manifest.json` (версия схемы, имя, статус), `summary.csv`,
`runtime_config.json` (если доступен), `code_metadata.json` (метаданные кодов,
включая Goppa `goppa_polynomial`/`parent_k`/`distance_lower_bound` для встроенных пресетов),
`experiment.log` (если доступен).

Импорт пакета никогда не использует `extractall`: читаются только пять
фиксированных имён из архива. Любые другие записи, `../`, абсолютные пути и
исполняемые файлы приводят к отклонению всего пакета. Ставим ограничения на размер архива,
размер отдельных файлов и количество записей в архиве.

## Ограничения MVP

- Одновременно выполняется один локальный subprocess; очередь сохраняется на уровне API, но отдельный планировщик очереди ещё не добавлен.
- Расширенный экспорт HTML и сравнение нескольких запусков находятся за пределами первого MVP.
- Встроенное семейство `bch_extended` зарезервировано схемой, но пока не поддерживается существующим `research.code_factory`.
- Основные этапы portable experiments, custom presets и Preview реализованы.
