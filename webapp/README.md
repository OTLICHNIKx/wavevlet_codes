# Wavelet / BCH Research UI

Локальная веб-оболочка для настройки, запуска и анализа исследований из пакета `research`.

## Архитектура

- FastAPI + SQLite хранят конфигурации и статусы экспериментов.
- Каждый запуск выполняется отдельным `python -m research.run_from_json` subprocess.
- stdout дочернего процесса содержит обычный лог и строки `PROGRESS {...}`.
- React/Vite отображает список запусков, прогресс, лог, таблицу `summary.csv` и Plotly-график.

## Docker

Из корня репозитория:

```bash
docker compose up --build
```

Интерфейс: http://localhost:3001

API: http://localhost:8001

(Порты `8001`/`3001` установлены по умолчанию, чтобы избежать конфликтов с другими проектами. Если нужны другие значения, их можно переопределить через переменные окружения:)

```bash
BACKEND_PORT=8000 FRONTEND_PORT=3000 docker compose up --build
```

Проверка: `GET http://localhost:8001/api/health`

Результаты сохраняются в `research_results/`, SQLite и пользовательские данные в `webapp_data/`.

## Локальный запуск

Backend:

```bash
pip install -r webapp/backend/requirements.txt
uvicorn app.main:app --app-dir webapp/backend --reload --port 8000
```

Frontend в отдельном терминале:

```bash
cd webapp/frontend
npm install
npm run dev
```

## Рабочий процесс

1. Выберите встроенный пресет в форме нового эксперимента.
2. Настройте число сообщений, seed, Eb/N0 и декодеры.
3. Проверьте конфигурацию. Backend построит реальные `G` и `H`, проверит размеры, ранг и ортогональность.
4. Запустите эксперимент и наблюдайте SSE-статус и live-log.
5. После завершения откройте график, выберите метрику и шкалу Y или перейдите к данным.

## Импорт готового `summary.csv`

Команда «Импорт эксперимента» в навигации позволяет загрузить уже
рассчитанный `summary.csv` (например, полученный от коллеги) и сразу
посмотреть графики/таблицы — **без повторного Monte-Carlo запуска**.

- Backend валидирует обязательные колонки (`code_name`, `code_family`, `n`, `k`,
  `decoder`, `ebn0_db`, `message_count`, `ber`, `frame_error_rate`) и семантику
  (диапазоны BER/FER, `success_count + failure_count == message_count`,
  согласованность `frame_error_rate`/`ber` с `frame_errors`/`bit_errors` и т.п.).
- Невалидный CSV отклоняется с конкретным списком причин, без создания эксперимента.
- Успешный импорт создаёт Imported Experiment с `source = "imported_csv"`,
  видимый в UI отдельным бейджиком, и открывается в той же странице
  результата, что и локально рассчитанные эксперименты (графики, таблица, фильтры).
- Импортированный из CSV эксперимент не имеет полного runtime config/лога:
  эти данные появляются только при импорте полного experiment package (следующий этап).

## Ограничения MVP

- Одновременно выполняется один локальный subprocess; очередь сохраняется на уровне API, но отдельный планировщик очереди ещё не добавлен.
- Пользовательские пресеты, расширенный экспорт PNG/SVG/HTML и сравнение нескольких запусков находятся за пределами первого MVP.
- Встроенное семейство `bch_extended` зарезервировано схемой, но пока не поддерживается существующим `research.code_factory`.
- Импорт полного experiment package (`.zip`), custom presets и Experiment Preview — следующие этапы.
